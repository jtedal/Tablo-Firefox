# Разработка Табло

Расширение использует Manifest V3 и работает в настольном Firefox 140+. Файлы из `src/` загружаются напрямую, без сборки JavaScript и установки npm-зависимостей.

## Ветки и документация

Текущие доработки ведутся в `dev`. Ветка `main` предназначена только для релизов. Коммиты и push выполняет владелец проекта самостоятельно.

При обновлении расширения меняйте пользовательский README и обновляйте скриншоты в `docs/screenshots/`. Снимки главной страницы, папки и недельной погоды делайте после проверки финального интерфейса в отдельном профиле Firefox. Готовьте документацию и изображения вместе с изменением. Правила для агентов находятся в [AGENTS.md](../AGENTS.md).

## Запуск и тесты

Для запуска выберите `src/manifest.json` через «Загрузить временное дополнение» на странице `about:debugging#/runtime/this-firefox`. После изменения файлов нажмите «Перезагрузить» рядом с расширением.

Для тестов нужен Node.js 22+:

```sh
npm test
```

Тесты проверяют модель данных, хранилище, получение названий и значков сайтов, перенаправления, погодные сервисы и кэш. Проверку интерфейса и разрешений выполняйте отдельно в Firefox.

## Упаковка

Нужен Python 3.9+ со стандартной библиотекой. В Windows:

```powershell
py -3 tools/build.py
```

В Linux и macOS:

```sh
python3 tools/build.py
```

Если команда `python` запускает подходящую версию Python, доступна также команда `npm run build`.

Результат появится в `dist/Tablo-Firefox-<версия>-unsigned.xpi`. В архив входят только файлы из `src/`. Скрипт нормализует порядок файлов, даты и атрибуты ZIP; при одинаковых исходниках и версии Python/zlib архив получается одинаковым.

## Структура проекта

```text
src/       файлы расширения
tests/     тесты Node.js
tools/     скрипт упаковки
docs/      документация и скриншоты
dist/      готовые архивы, исключены из Git
```

## Выпуск версии

Обновите версию в `package.json`, `src/manifest.json`, подписи внизу настроек в `src/newtab.html` и строке `User-Agent` в `src/met-weather.js`.

Упаковка не подписывает расширение. Для постоянной установки в обычный Firefox нужна подпись Mozilla. Новую версию отправляйте через страницу существующего дополнения в [Developer Hub](https://addons.mozilla.org/developers/), чтобы она считалась обновлением. Порядок публикации описан в [документации Mozilla](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/).

## Языки и начальные сайты

`settings.language` принимает `auto`, `ru` или `en`. В автоматическом режиме сначала используется `browser.i18n.getUILanguage()`, затем язык браузера из `navigator`; русский выбирается для `ru`, английский — для остальных языков. Ранний локальный снимок восстанавливает ручной выбор до основного модуля. После чтения основного хранилища настройки из него имеют приоритет над снимком.

Каталоги `src/locales/` используются и ранними скриптами, и приложением. `_locales/` отвечает за название и описание дополнения в Firefox независимо от ручного выбора языка Табло. Начальный набор и поисковик определяются языком только при новой установке или явном сбросе. При сбросе выбранный режим языка сохраняется. Смена языка существующей страницы не меняет сохранённые сайты, папки, поисковик или названия пользователя.

Встроенные значки находятся в `src/assets/sites/`, источники перечислены в `NOTICE.md`. `site-icons.js` сопоставляет доверенные домены с локальными файлами; загруженный favicon и ручной текстовый значок имеют приоритет. Для получения этих значков во время работы расширения сеть не используется.

## Поисковики

`settings.searchEngines` хранит включённые поисковики: от одного до шести уникальных идентификаторов из `google`, `yandex`, `bing`, `duckduckgo`, `brave`, `ecosia`. Выбранный `settings.searchEngine` должен входить в этот список. По умолчанию включены Google и Яндекс, а выбранный поисковик нового профиля зависит от языка. Смена языка не меняет этот выбор.

Старые данные без `searchEngines` получают Google и Яндекс, а сохранённый выбранный поисковик сохраняется и добавляется в список при необходимости. Сайты и остальные настройки не заменяются. Пустой список, неизвестные или повторяющиеся идентификаторы, неверный тип списка и выбранный поисковик вне списка отклоняются при проверке данных.

## Погода и загрузка страницы

Встроенные значки интерфейса, плиток и погоды создаются общим `src/icons.js` через `createElementNS`. Каталог содержит только фиксированные SVG-фигуры и их атрибуты; HTML-строки в интерфейс не вставляются. Этот скрипт подключается до раннего отображения погоды и плиток.

HTML сайта для названия и значка разбирается через `DOMParser` в отдельный документ с начальным `<body>`. Так `title` и `base` из `noscript` в шапке страницы остаются внутри резервного содержимого, которое исключается после разбора. Из документа извлекаются текст и проверенные адреса, его узлы не переносятся в интерфейс Табло.

На повреждённой разметке результат восстановления документа может отличаться от прежнего разбора через `template`: например, незакрытые `table` или `select` внутри `noscript` могут захватить последующий `title`. В этом случае название считается отсутствующим; отдельный HTML-парсер для воспроизведения прежнего поведения не используется.

Минимум настольного Firefox остаётся 140. Валидатор может выдавать `KEY_FIREFOX_ANDROID_UNSUPPORTED_BY_MIN_VERSION`: встроенное согласие на передачу данных появилось в Android 142. Android не заявлен в манифесте и не выбран в карточке AMO; добавлять `gecko_android` ради подавления этого предупреждения не нужно.

Open-Meteo использует кэш на 15 минут и предоставляет суточные минимумы, максимумы и вероятность осадков. MET Norway передаёт временной ряд: Табло группирует точки по местным календарным дням и показывает диапазон их температур. Этот диапазон отличается от суточных экстремумов. Ощущаемая температура и вероятность осадков для MET Norway не вычисляются.

Для MET Norway соблюдается `Expires`, в том числе при ручном обновлении. После истечения срока используется `If-Modified-Since`. HTTP 429 включает паузу по `Retry-After`. Сохранённые данные доступны при ошибке сети в течение шести часов.

Фон, часы, поиск и сохранённая погода отображаются до загрузки основного модуля. Плитки появляются с анимацией. Кадр, который Firefox показывает до первой отрисовки страницы расширения, сама страница изменить не может. Пользовательские стили `userChrome.css` в проект не входят.
